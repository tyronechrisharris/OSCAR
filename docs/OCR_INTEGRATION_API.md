# OSCAR OCR Integration API

This document describes the API workflow for integrating an external Optical Character Recognition (OCR) system with OSCAR. The OCR system reads container numbers from video files associated with alarming occupancies and automatically provides the verified container number back to OSCAR so it can be added to the adjudication details.

## Overview

The general integration workflow is as follows:
1. **Authentication:** Authenticate with OSCAR using API Keys via Basic Auth.
2. **Retrieving Occupancies:** Poll the OSCAR backend for recent occupancies and extract the `occupancyObsId` and `videoPaths`.
3. **Downloading Video Files:** Fetch the video files associated with the occupancy from the bucket endpoint.
4. **Submitting the Container Number:** Perform OCR on the video, extract the container number, and submit it back to OSCAR via the Adjudication command endpoint, placing the container number in the `vehicleId` field.

## 1. Authentication

All requests to the OSCAR backend must be authenticated. The OCR service should use API Keys provisioned in OSCAR, transmitted using HTTP Basic Auth.

-   **Username:** The client ID (e.g., `api-client`).
-   **Password:** The API Key generated by OSCAR.
-   **Header:** `Authorization: Basic <base64-encoded-credentials>`

## 2. Retrieving Alarming Occupancies

To find **alarming occupancies** that require OCR processing, you will need to poll the ConSys API endpoints. OCR should *only* be performed on occupancies that resulted in an alarm (e.g., Gamma, Neutron, or Gamma-Neutron alarms). The recommended approach is to query data streams or observations and filter for alarming events.

*   **Endpoint:** `<connectedSystemsEndpoint>/systems/{id}/datastreams` (where `{id}` is the system ID, typically the lane ID).
*   **Method:** `GET`
*   **Headers:** `Authorization: Basic ...`

From the resulting observations, you must filter to process only the records where an alarm condition is present (e.g., checking `gammaAlarm=true` or `neutronAlarm=true` in the result data). From these filtered observations, extract:
-   `occupancyObsId`: The unique ID of the occupancy observation.
-   `videoPaths`: A list of file paths for the video files recorded during the occupancy.
-   `controlStreamId`: The ID of the adjudication control stream for the lane (usually formatted as `{lane_uid}_adjudicationControl`).

*Note: `<connectedSystemsEndpoint>` is dynamically constructed based on the node's address and base path (e.g., `https://<node-address>:<port>/api/sensorhub/sos`).*

## 3. Downloading Video Files

Once the `videoPaths` are extracted from the occupancy observation, the OCR service must download the video files for processing.

*   **Endpoint:** `<oshPathRoot>/buckets/<videoPath>`
    *   Example: `https://<node-address>:<port>/api/sensorhub/buckets/video/my_lane/2023-10-27T10:00:00Z.mp4`
*   **Method:** `GET`
*   **Headers:** `Authorization: Basic ...`

The OCR system will download the MP4 file and process its frames to extract the container number.

## 4. Submitting the Container Number

After successfully extracting the container number, the OCR service submits this information back to OSCAR by issuing an adjudication command. The container number is passed in the `vehicleId` field of the command payload.

*   **Endpoint:** `<connectedSystemsEndpoint>/controlstreams/<controlStreamId>/commands`
    *   Where `<controlStreamId>` is typically `{lane_uid}_adjudicationControl`
*   **Method:** `POST`
*   **Headers:**
    *   `Authorization: Basic ...`
    *   `Content-Type: application/json`

### Payload Structure

The command payload must be a JSON object conforming to the Adjudication command parameters structure.

```json
{
    "parameters": {
        "feedback": "OCR automated extraction",
        "adjudicationCode": 0,
        "isotopesCount": 0,
        "isotopes": [],
        "secondaryInspectionStatus": "NONE",
        "filePathCount": 0,
        "filePaths": [],
        "occupancyObsId": "<extracted-occupancy-obs-id>",
        "vehicleId": "<extracted-container-number>"
    }
}
```

-   **`occupancyObsId`:** The ID of the occupancy retrieved in step 2.
-   **`vehicleId`:** The container number successfully read by the OCR system.
-   *Other fields:* Fill out standard default values (e.g., `adjudicationCode: 0`, `secondaryInspectionStatus: "NONE"`) if the OCR system is only appending the container number. If updating an existing adjudication, merge existing values accordingly.
